# OCR 精度与复核（0.2.5）

针对用户图 `A\mathbf{v}=\lambda\mathbf{v},\qquad\mathbf{v}\ne\mathbf{0}` 的改进，覆盖公式、智能模式和图片粘贴共用的后台识别链路。

## 原因与处理

原图在本机已有 0.2.2 包及修改前源码下可以识别完整，因此不能宣称原始 400×104 文件稳定复现了用户报告的同一段错误。改变纸色或增加外侧留白后，则实际出现了空 `array`、孤立 `\hline`、字母误读，且旧代码错误地把这些结果标为成功。

1. **输入**：先在原分辨率检测背景和笔画，再裁掉外侧空白。保留公式全部区域，包括远离主式的条件和独立标点；不按连通域面积删除笔画。浅色/深色统一白底，保留抗锯齿，低对比度才拉伸灰度。缩放保持比例。
2. **推理**：正常输入只解码一次。低置信度、非法结构、可疑空数组或格线/列数不符才改变边距再试一次，最多两次，不增加模型或并发会话。token 几何平均概率用于同图候选选择，不代表准确率。
3. **结构**：检查花括号、环境配对和表格规则作用域；要求正常 EOS。真实表格可见左右边框和贯穿高度的竖线时，用格线核对列数。不重建无法确定的单元格。
4. **整理**：仅当图像确认为单行、外层为简单无框 `array`、只有一行有效内容且至少两行为空时，允许提取有效内容。优先用再次识别的完整候选，不能凭空补写模型漏掉的条件。无法解决的结果标记复核。`matrix`、`cases`、`aligned`、复杂列声明、外层括号和真实表格不折叠。
5. **输出**：删除数学 token 多余空白，保留 `\alpha x` 的控制词边界、`\ ` 等显式空格和 `\text{...}` 中的文字。智能模式中需要复核的真实表格仍保留整表，不拆成文字行。

## 本机验证

`test/fixtures/ocr/` 保存用户原图和 9 张有明确源公式的生成图。`scripts/validate-ocr-accuracy.mjs` 还生成 5 个纸色/深色/留白变体，并检查 4 个智能模式场景。使用已经安装的包，无下载或图形界面：

```sh
npm run build
npm run validate:ocr-accuracy -- --pack '/path/to/ocr/2026-08-18.1' --report /tmp/ocr-report.json
```

数值和验证结果见本次 `project_memory.md` 记录。两张带框表格是已知模型边界：仍可能多生成行列或遗漏边线，因此测试要求保留表格并标记复核，不将其计为识别准确的样例。

本次正式/测试交付文件为 `silk-math-preview-0.2.5-ocr.vsix` / `silk-math-preview-test-0.2.5-ocr.vsix`，内部版本 0.2.5。以已验证 0.2.4 为底座，仅替换 OCR 与版本/说明；工作区同期进行的布局修改保留在源码中，没有混入此次独立 OCR 包。包内最终 Worker 完成 19 次检查，其中 16 次识别通过，3 次真实表格保留并提示复核。原图输出与规范 `\mathbf` 写法渲染出的 SVG 完全相同。

## 边界

- 继续使用 `2026-08-18.1` 模型包。图像仅在本机 Worker 内处理，不上传；本次没有训练或替换模型。
- 结构校验不是完整 TeX 语法检查，也不能检测所有语义错误。没有边框的真实表格和多行公式在视觉上可能相似；无法确认时保留结构。
- 复杂表格、合并单元格、模糊/手写公式、字体粗细和超长公式仍需核对。新流程减少已验证的留白/背景问题，不承诺所有图片准确。
- 保留现有 20 MB / 16 MP 输入限制、取消/超时销毁和默认 60 秒空闲释放。识别模块不进入普通公式预览热路径。

参考：[固定量化模型的预处理配置](https://huggingface.co/Brian314/pix2text-mfr-quantized/blob/4b1c45ae364c5e97c644281b89c25987ee1bce8c/preprocessor_config.json)、[Pix2Text 的推理与后处理实现](https://github.com/breezedeus/Pix2Text/blob/main/pix2text/latex_ocr.py)。本次保留现有等比例输入约定，背景与结构处理基于本项目实际复现结果。
