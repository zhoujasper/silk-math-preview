# 0.1.80 性能验证（2026-09-07）

本机 Node 26.8.1、macOS；修改前后使用相同输入，表格/单位以变化表达式避开 SVG 结果缓存。
数字只代表此次运行，不是跨设备承诺。旧源码来自本轮之前保留的 0.1.78 数字/宏支持快照，
该部分实现与本轮开始的 0.1.79 相同。

| 样例 | 修改前 p50 / p95 | 修改后 p50 / p95 |
| --- | --- | --- |
| 24 个数量和符号单位 | 12.330 / 15.487 ms | 7.092 / 8.384 ms |
| 40 个普通数字 | 5.683 / 7.428 ms | 5.997 / 7.553 ms |
| 4000 条宏和 4000 条依赖 | 27.752 / 83.732 ms | 6.324 / 7.787 ms |
| 5000 位整数分组 | 13.246 / 16.944 ms | 0.059 / 0.081 ms |

普通公式完整 Worker 往返：冷启动 p50/p95 53.05/58.67 ms，热渲染 4.38/5.90 ms；
27,378 字符有界扫描 p95 0.585 ms；空闲回收后重启通过。普通公式修改前热渲染为
3.72/5.33 ms，冷启动 49.49/54.57 ms，本次没有观察到所有路径都变快；增加了显示能力，
同目录还有其他功能更新，测试期间的调度/GC 也会影响小样本。

显式 GC 后，重复切换 120 个宏上下文并清空渲染器，测试进程 JS heap 从约 17.27 MiB
变为 15.00 MiB。此项包含 MathJax/脚本运行时，与 VS Code 总内存/RSS、OCR 模型内存不是一回事。
每帧释放 parse tree、node lists、最后的 SVG/table wrapper；最多保留 2 个宏上下文。

主线程的 500,000 字符正文回归验证：在最后一条声明之后输入普通公式，只调用一次带 Range
的 getText，读取 128 字符；getSnapshot 返回同一个语义快照。新增宏仍刷新，旧文档缓存淘汰后能
按需重建；不同依赖的读取顺序和未保存缓冲区继续通过测试。

预算：主 bundle < 200 KiB；VSIX < 2.5 MiB；SVG 结果 64 条/8 MiB；文档解析 12 条/估算
16 MiB，依赖解析 128 条/估算 16 MiB，快照缓存各 16 条/估算 8 MiB，路径 512 条/估算
128 KiB；单位和选项各 64 条/估算 32 KiB。预算统计的是缓存权重，不是进程硬内存上限。
默认渲染 Worker 空闲 60 秒回收，不引入后台轮询任务。

复现：`npm run verify`、`node --expose-gc scripts/benchmark-compat.mjs`、
`node scripts/benchmark-parser.mjs`。后者可用 `SILK_BENCH_SOURCE` 指向旧源码快照。

未运行浏览器或 Extension Host 视觉自动化；最终 UI 由用户手动验收。

交付包两个通道的 Worker 又在 VS Code Node 24.18.1 实跑，各通过 7 项数字/宏/表格/错误恢复检查；这些运行没有打开编辑器 GUI。
